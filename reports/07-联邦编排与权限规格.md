# forge 联邦编排与权限约束规格

## 1. 联邦的权限继承模型

权威实现是 `policy.py:Policy.child()` 与 `Mode.clamp_to()`。三档继承规则：

- **mode**：子只能降不能升。`ceiling = parent.mode`，请求值 clamp 到 ceiling。
- **规则集**：`allow/ask/deny/forbidden_programs/deny_patterns` 原样复制，子**不可增删**。因此 deny 恒胜对孙代同样成立。
- **sandbox**：整对象继承，不放大也不收窄；写路径校验用同一个 `workspace` 锚点。

```
def child(mode_req=None):
    ceiling = parent.mode                 # BYPASS 视作自身上限
    mode    = clamp(mode_req or parent.mode, ceiling)
    return Policy(mode, sandbox=parent.sandbox,
                  allow=parent.allow, ask=parent.ask, deny=parent.deny,
                  forbidden_programs=…, deny_patterns=…)

def evaluate(tool, args, touching):
    if matches(deny, tool):                     return DENY      # 1 规则禁
    if command and command_denied(command):     return DENY      # 2 命令禁
    if tool in WRITE_TOOLS and not sandbox.allows_write(t): return DENY  # 3 沙箱
    if tool=="shell_exec" and sandbox is READ_ONLY:         return DENY
    if matches(ask, tool):   return ALLOW if mode is BYPASS else ASK     # 4
    if matches(allow, tool): return ALLOW                                # 5
    return baseline(mode)                                                # 6

def resolve_ask(d): return DENY if d is ASK and non_interactive else d
```

编排者深度 0，子 agent 深度 +1，孙 agent 再 +1；每一层都重新走 `child()`，因此钳制是**逐层复合**的，不是只在顶层生效。

## 2. 跨进程的权限问题

`loop.py:_spawn_handler()` 当前是**进程内**构造 `Agent`，子与父共享 Policy 对象，ceiling 是真实内存约束。`--swarm` 下子 agent 跑独立进程，纸面约束会失效，必须做三件事：

1. **启动期物化**：父把 clamp 后的 `mode` 通过 `--permission-mode` 与 `--subagent-permission-mode` 显式写入子进程命令行，禁止子进程从配置文件自取 mode（配置文件可能比父更宽）。
2. **子进程自证**：子启动后把 `Policy.mode.value` 写入自己 `session_meta` 的 `policy_mode`；父在回收时比对注入值与自证值，不一致即标记 `permission_mismatch` 并作废该结果。
3. **非交互坍缩**：子进程强制 `non_interactive=True`，使 `resolve_ask` 把一切 ASK 降为 DENY——独立进程没人可问，ASK 不能悬空成 ALLOW。

关键不变量：**子进程不得成为权限权威**。父只信自己注入的 ceiling，子的任何自述都只作校验输入。

## 3. 任务分配协议

任务描述符（建议字段）：

```
{ id, goal, inputs:[path…], deliverable:{schema},
  capabilities:[tag…], model_class:"small"|"strong",
  ceiling_mode, sandbox_root, allowed_tools:[glob…],
  timeout_s, max_tokens, parent_spawn_id }
```

- **能力匹配**：用 `CapabilityLibrary` 索引 + `ToolRegistry.names()/search()` 求交集，`capabilities` 全命中才派发。
- **模型档位**：`model_class:"small"` 直接映射为 `router.complete(messages, small=True)`——`loop.py:222` 已是 `small=False` 的调用点，改传描述符字段即可，无需新机制。
- **工具面**：`allowed_tools` 落到 `build_builtin_registry(expose=…)`，比在 system prompt 里"请只用这几个工具"强一个数量级。
- **只能给便宜模型**的语义 = `model_class="small"` 且描述符里 `max_tokens` 收紧；若派发方尝试升档，编排器拒绝而不是静默升级。

## 4. 结果回收与去毒

现有链条：`sanitise_child_output()` → `INJECTION_RE` 正则替换 `[redacted-directive]` → 截断到 `max_tool_result` → 包成 `ToolResult(content=…)` → 父把结果作为 **user 消息**注入，绝不作为 system/assistant。

补齐三点：

- 清洗必须在**每一层** `_spawn_handler` 调用（现已如此），多级拼接不能只在顶层清一次。
- `INJECTION_RE` 只覆盖 `system-reminder/system/instructions/assistant`，需扩展 `<tool_result>`、`<tool_call>`、`SYSTEM:` 的变体与零宽字符。
- 子输出只允许作为**数据**进入父上下文，禁止父方把子文本原样拼进自己的 system prompt。

## 5. 预算与限额

`LoopLimits` 默认 `max_depth=2, spawn_budget=8`；宿主硬顶 5 层 / 200 次。**生效值 = min(配置, 宿主硬顶)**，配置只能更严。

- **深度**：`depth >= max_depth` 即拒。深度 2 表示编排者外最多两级（子 + 孙）。
- **扇出**：现无逐节点上限，只有全局 `budget`。建议补 `max_fanout`，否则单节点可吃光全预算。
- **总 spawn 数**：`budget` 是**共享可变 list**，父子同引用，先扣后 spawn，天然全局计数。
- **算术**：扇出 f、深度 d 的满树规模 `N = 1 + f + f² + … + f^d`。f=3、d=2 → 1+3+9=13，故 `spawn_budget` 必须 ≥13，否则树会中途截断且截断点不确定。
- **单 worker 花费**：`RunReport.usage` 累加 prompt/completion tokens，`Session.tokens()` 汇总。每 worker 设 `max_tokens`，超限即中止并回收部分结果；编排器总账不得超过 Σ 各 worker 配额。

## 6. 失败与降级

`_spawn_handler` 已保证**子异常不杀父**（捕获后 `subagent_error` + `ok=False`）。降级阶梯：

1. 同描述符重试一次（仅对可重试错误，参照 `model.py` 的异常分类）；
2. 降档到 `model_class="small"` 重试；
3. 缩小 `inputs`/`deliverable` 后重派给另一个 worker；
4. 超时/协议不兼容（返回体不满足 `deliverable.schema`）时，标记 `incompatible` 并上抛给编排者；
5. 全失败 → 该任务标 `failed`，编排者带**部分结果**继续，不整树回滚。

`id` 保证重派幂等；写操作前有 `checkpoints.snapshot()`，重派不会双写。

## 7. 审计

所有事件经 `Agent._emit()` → `Session.append(etype, **payload)` 落到同一 JSONL，带单调 `ordinal`，`session_meta` 为 ordinal 0。派发/回收必须留：

- `subagent_spawn{task[:300], mode, depth, budget_left}`（已有）
- `subagent_error{error}`、`subagent_result{chars, steps}`（已有）
- **需补**：`spawn_id`、`ceiling_mode`（注入值）、`policy_mode`（子自证值）、`worker_tokens`、`parent_session_id`。

跨进程时子写自己的会话文件，父在 `subagent_spawn` 里记录子的 `session_id`，靠 `spawn_id` 串联。决策级痕迹由 `Policy.audit_line()` 输出（含 mode/sandbox/tool/decision）。`SessionIndex.rebuild()` 可随时从日志重建汇总，日志是唯一事实。

## 9. 自检清单（离线可验证）

1. `Policy(mode=AUTO).child(Mode.BYPASS).mode is Mode.AUTO`。
2. `Policy(mode=PLAN).child(None).mode is Mode.PLAN`；`child(BYPASS).mode is PLAN`。
3. 子策略的 `deny` 与父 `deny` 逐元素相等（同一元组内容）。
4. `deny=("shell_exec",)` 且 `allow=("shell_exec",)` 时 `evaluate` 返回 `DENY`。
5. `sandbox=WORKSPACE_WRITE` 下对 workspace 外路径的 `write_file` 返回 `DENY`。
6. `non_interactive=True` 时 `resolve_ask(ASK) is DENY`。
7. `depth == max_depth` 时 `_spawn_handler` 返回 `ok=False` 且含 `max subagent depth`。
8. 连续 spawn `spawn_budget` 次后 `budget[0] == 0`，下一次返回 `spawn budget exhausted`。
9. `child.budget is parent.budget`（共享引用，非拷贝）。
10. `sanitise_child_output("<system-reminder>x</system-reminder>")` 结果不含 `system-reminder`。
11. 子输出长度被截到 `max_tool_result`。
12. `Session` 事件 `ordinal` 严格递增，首条为 `session_meta`（ordinal 0）。
13. 延迟工具在 `activate` 前不在 `visible()`；`no_defer` 工具始终可见。

## 10. 最容易被绕过的三处

1. **间接执行的命令黑名单**。`deny_patterns` 是对 command 字符串的正则，`powershell -EncodedCommand` 已被拦，但"先 `write_file` 落一个 `.ps1`/`.bat`，再 `shell_exec` 执行它"不触发任何模式；黑名单拦形态，拦不住语义等价物。
2. **进程内共享对象即提权通道**。`_tool_context()` 把 `agent` 自身塞进 `extras`，且 `budget` 是共享可变 list、`policy` 是共享引用。任何能取到 `ctx.extras["agent"]` 的工具（含被注入的第三方能力）都能改 `budget` 或直接替换 `policy.mode`，子 agent 即可自我提权。
3. **去毒只做正则替换**。`INJECTION_RE` 不覆盖 `<tool_result>`/`<tool_call>` 与代码块内的仿冒提示，也不处理零宽字符拼接；父把子输出当 user 消息注入后，模型仍可能把其中文本当作上下文指令执行，多级嵌套下被 redact 的片段还可被重新拼出。
