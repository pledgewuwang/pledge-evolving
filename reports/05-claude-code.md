# Claude Code 智能体框架解剖

## 1. 形态与定位

从 `~/.claude` 顶层目录看，这是一个以**本机文件系统为状态存储**的 CLI 智能体框架，而非纯无状态的 API 封装。实测目录包含：`sessions/`、`projects/`、`plugins/`、`plans/`、`tasks/`、`file-history/`、`shell-snapshots/`、`backups/`、`cache/`、`session-env/`、`telemetry/`、`history.jsonl`，以及多份带时间戳的 `settings.json.bak-*` 备份。

- `projects/` 按工作目录路径编码为子目录名（如 `C--Users------openclaw-autoclaw-workspace-agent-f5hc9`），说明会话与「项目工作目录」强绑定，而非全局一份历史。
- `sessions/` 下抽样到 `41560.json` 与配套的 `.key` 文件（同名 hash 后缀），暗示会话数据可能有加密/校验机制，而非纯明文 JSON（自述）。
- `plugins/` 下有 `marketplaces/` 和 `known_marketplaces.json`，说明插件生态走「市场注册表」模式，而非单纯本地目录扫描。
- `plans/`、`tasks/`、`file-history/`、`shell-snapshots/` 顶层目录存在但未展开细节，只能确认这些是独立的基础设施模块（分别对应计划态、任务追踪、文件历史快照、shell 快照），具体机制以下第 2、4 节结合自述知识补充。
- 多份 `settings.json.bak-*` 备份文件的存在说明配置变更会被自动或手动快照，这是一种轻量级的配置版本控制习惯。

## 2. 主循环

单会话的核心是一个「LLM 输出 → 工具调用 → 工具结果注入 → 再次调用 LLM」的循环，直到模型不再请求工具为止（自述）。上下文压缩策略上，系统提示中明确写有「当对话变长时，部分或全部上下文会被自动摘要」的机制说明，这与 evidence 中 `settings.json` 里 `CLAUDE_CODE_MAX_CONTEXT_TOKENS: 983616` 这一实测配置项相呼应——存在一个显式的上下文 token 上限环境变量，压缩很可能在接近该阈值时触发（自述：具体触发算法未在证据中体现）。`history.jsonl`（16255 字节）作为顶层文件，推测承担跨会话的操作历史落盘（自述）。

## 3. 工具与权限

工具集合覆盖文件读写、Bash/PowerShell 执行、搜索、任务编排、子代理调用、定时任务、Web 访问等，且明确要求「优先用专用工具而非 Bash」（自述，来自当前系统提示的工具选择规范）。权限上存在多档 permission-mode，未获自动批准的工具调用会触发用户确认（自述）。

`settings.json` 分层机制在 evidence 中有直接证据：本机配置只有 `theme` 和 `env` 两个字段，`env` 段包含 `ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_BASE_URL`、`ANTHROPIC_MODEL` 等键——这说明**配置文件层可以覆盖进程级环境变量**，实现了「无需改系统环境变量即可切换模型代理端点」的能力（实测）。同时 `ANTHROPIC_DEFAULT_HAIKU_MODEL`/`SONNET_MODEL`/`OPUS_MODEL` 与 `CLAUDE_CODE_SUBAGENT_MODEL` 分别独立配置，说明框架允许**按角色（主模型 vs 子代理模型）分别指定模型版本**，这是实测到的一个细粒度控制点。

## 4. 上下文工程

CLAUDE.md 作为项目级记忆文件被自动加载进系统提示，形成「仓库知识」层（自述）。子代理（Agent 工具调用）拥有独立、隔离的上下文窗口，只有其最终报告文本会被父会话看到，中间的工具调用与思考过程不会污染主上下文（自述，且被当前系统提示明确强调）。`shell-snapshots/` 顶层目录的存在，结合命名推测承担「记录 shell 会话状态快照，供压缩后恢复或跨轮次复用」的角色；`file-history/` 顶层目录推测对应「文件编辑前后版本快照，用于 Edit/Write 操作的可追溯与潜在回滚」（均为自述推测，evidence 未展开其内部结构，不可作实测结论）。

## 5. 扩展生态

- **Subagents**：预定义角色（如 Explore、Plan、general-purpose），工具权限可按角色裁剪（自述，当前系统提示列出的 agent 类型即为证据内证据）。
- **Skills**：打包的任务指令集，通过 `/skill-name` 或描述匹配触发，可选择在主上下文或子代理中执行（自述）。
- **Plugins**：evidence 证实以 `marketplaces/` + `known_marketplaces.json` 的市场注册表形式管理，说明插件分发走中心化索引而非纯本地脚本（实测目录结构）。
- **MCP**：外部工具协议接入点，供第三方服务注册为可调用工具（自述）。
- **Slash commands / output styles**：前者是用户可直接输入的固定指令别名，后者调整响应风格而不改变工具能力（自述）。

## 6. 最值得抄的 6 个设计

1. **项目路径隔离会话存储**（`projects/` 按 cwd 编码目录）。解决多项目历史混淆问题。机制：工作目录字符串编码为文件夹名（实测）。移植成本：低。
2. **配置层覆盖环境变量**（`settings.json.env`）。解决「不同项目/代理需要不同模型端点却不想污染全局环境」的问题。机制：进程启动时读取配置注入 env（实测）。移植成本：低。
3. **按角色分模型**（主模型/Haiku/Sonnet/Opus/子代理独立配置）。解决成本与能力的粒度平衡问题，简单任务下沉给子代理用便宜模型。机制：多个独立 env 键位（实测）。移植成本：中。
4. **子代理上下文隔离**。解决主上下文被中间探索过程污染、快速膨胀的问题。机制：子代理独立上下文窗口，只回传结果摘要（自述）。移植成本：中（需要独立的会话/上下文管理层）。
5. **配置自动备份**（多份 `settings.json.bak-*`）。解决配置误改难回溯的问题。机制：写入前快照，带时间戳命名（实测）。移植成本：低。
6. **技能/插件的市场化注册表**（`marketplaces/`）。解决扩展能力发现与版本管理问题。机制：中心索引 + 本地缓存（实测目录结构存在，具体协议自述）。移植成本：中高。

## 7. 明确短板与风险

- 会话/配置状态高度依赖本机文件系统（`~/.claude` 单机目录），缺乏证据表明有云端同步或多机协作机制，团队协作场景下需要额外方案（基于 evidence 缺失推断）。
- `settings.json` 中 `ANTHROPIC_BASE_URL` 指向 `127.0.0.1:8787` 的本地回环代理，说明当前环境使用了自定义模型转发层——这类配置一旦拼写错误或代理宕机会直接导致框架不可用，属于单点风险（实测）。
- 备份文件（`.bak-*`）会无限堆积在同一目录，缺乏自动清理证据（`.last-cleanup` 文件存在但未知其清理范围），长期可能造成目录膨胀。
- 上下文压缩的具体触发算法、子代理结果的可信度校验机制均未在 evidence 中体现，只能自述带过，实际生产化时需要自行补充可观测性。

## 8. 对「自研统一智能体框架」的具体建议

1. 会话状态按「工作目录哈希/编码」分区存储，避免跨项目历史串台。
2. 配置文件显式支持 `env` 覆盖段，让模型端点/密钥可随项目切换而不改全局环境变量。
3. 为主模型与子代理模型分别开独立配置键，允许「贵模型决策、便宜模型执行」的成本分层。
4. 子代理调用必须走独立上下文，父会话只接收结构化结果摘要，不接收子代理的原始工具调用轨迹。
5. 关键配置文件写入前自动打时间戳备份，且定期清理策略要显式落地（避免只有备份没有清理）。
6. 扩展能力（技能/插件）走注册表+本地缓存模式，而不是散落的本地脚本目录，便于发现与版本管理。
7. 明确定义上下文压缩的触发阈值为可配置项（对应本例的 `MAX_CONTEXT_TOKENS`），并将其作为一等公民配置暴露给用户。
8. 对所有「自述推测」类设计（如压缩算法、快照回滚细节）在自研前先做实测验证，不要直接照搬未经验证的机制假设。
